# Monitor（油猴脚本）

一个在网页右下角运行的开发调试大屏，监控：

- `fetch` 与 `XMLHttpRequest` 响应；
- `localStorage` / `sessionStorage` 初始值及后续增删改；
- `window` 全局属性的完整初始基线，以及新增、删除和浅层变化；
- 所有变化的统一时间线。

IndexedDB 按当前需求不实现。

## 安装

1. 安装 Tampermonkey；
2. 新建脚本；
3. 将 `runtime-monitor.user.js` 的全部内容粘贴并保存；
4. 刷新需要监控的网页；
5. 点击右下角 **Monitor** 打开面板。

默认 `@match` 为所有网页。建议实际使用时改成目标站点，例如：

```js
// @match https://example.com/*
```

## 内存保护

默认限制：

- 最多保留 200 条网络记录；
- 每条 fetch/XHR 响应最多保留 256 KB 文本；
- 所有网络请求文本合计约 5 MB，超出后从最旧记录开始淘汰；
- 同时最多读取 8 个 fetch 响应体；更高并发的请求只记录元数据；
- 变化时间线最多保留 500 条；
- Storage 单值最多展示 16K 字符；
- Window 只存受限预览和浅层指纹，不保留全局对象引用。

Window 初始基线及函数仍会参与监控，但默认不在列表中呈现，以避免浏览器原生构造器和函数淹没业务变量。需要排查时可在面板底部开启 **显示函数** 或 **显示初始全局**。

Window 对象会额外建立受限的全文搜索索引。索引包含嵌套属性路径和基础值，默认最多深入 5 层、访问 300 个节点、单变量保留 16K 字符，全部 Window 索引合计最多约 2M 字符。扫描只读取数据属性，getter/setter 会被跳过，循环引用会被安全终止。这样可以搜索嵌套对象内容，同时控制扫描开销和内存占用。

面板底部可以即时调整网络请求条数、单响应上限和网络文本总量。fetch 响应通过克隆后的流分块读取，到达上限就取消读取；有明确且超限的 `Content-Length` 时直接跳过响应体。二进制响应只记录元信息。

## 行为边界

- 使用 `document-start` 尽早安装 Hook，但仍看不到安装前、Worker 或 Service Worker 内部已经发生的请求；
- fetch 在响应头返回后立即进入列表，响应正文随后异步补充，因此流式或长连接 POST 也能及时显示；
- 浏览器自动生成的 CORS 预检 OPTIONS 不经过页面 JavaScript，油猴无法捕获；页面代码显式发起的 OPTIONS 可以捕获；
- XHR 的响应体已经由页面加载进内存，脚本只保存有限文本副本；
- Storage API 写入由 Hook 捕获，直接属性写入和漏掉的变化由每秒扫描兜底；
- Window 扫描可发现属性新增、删除、替换和有限的浅层变化，不会递归遍历整个对象图；
- getter 不会被主动执行，避免扫描产生页面副作用；
- 导出内容同样是受限预览，可能包含业务数据，请在分享前检查敏感信息。

## 面板操作

- **暂停/继续**：暂停时不再采集或扫描；
- **清空记录**：清除网络历史与变化时间线，保留当前 Storage/Window 快照；
- **导出**：下载当前受限快照 JSON；
- **搜索**：全文搜索名称、URL、响应内容、Storage 值及 Window 嵌套对象的属性路径和值；
- 搜索结果会显示命中位置附近的内容，并将关键词标为红色粗体；
- 点击搜索结果后，详情区会单独列出所有匹配上下文（最多 20 处），并同步高亮详情 JSON 中的关键词；
- **复制详情**：复制当前选中记录的标题、匹配上下文和格式化 JSON；
- **显示函数**：默认关闭，控制 Window 列表是否呈现函数；
- **显示初始全局**：默认关闭，控制 Window 列表是否呈现脚本启动时已有的全局属性；
- **网络/Storage/Window/变化**：切换数据源。

## 本地验证

语法与 Hook 烟雾测试不需要安装依赖：

```bash
node --check runtime-monitor.user.js
node tests/runtime-monitor.smoke.mjs
```

浏览器测试页为 `tests/browser-fixture.html`，通过本地 HTTP 服务打开后会自动产生 fetch、XHR、Storage 和 Window 测试数据。
